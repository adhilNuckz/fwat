🔧 §1 — Service Management Commands

The dashboard runs as a systemd service named wa-dashboard. Use the commands below to control it.

Check service status

sudo systemctl status wa-dashboard

Follow live logs (Ctrl+C to exit)

sudo journalctl -u wa-dashboard -f

Restart the service

sudo systemctl restart wa-dashboard

Stop the service

sudo systemctl stop wa-dashboard

Enable auto-start on boot

sudo systemctl enable wa-dashboard

View last 100 log lines

sudo journalctl -u wa-dashboard -n 100 --no-pager
ℹ️
Tip: Run systemctl status wa-dashboard first after any configuration change to confirm the service started correctly before tailing logs.

🔐 §2 — Custom Authentication

The dashboard supports HTTP Basic Authentication via environment variables in the systemd service unit file. Follow the steps below to change credentials.

Step 1 — Edit the service unit file

sudo nano /etc/systemd/system/wa-dashboard.service

Step 2 — Locate and update the Environment variables

Find the [Service] section and edit (or add) these lines:

# /etc/systemd/system/wa-dashboard.service
[Unit]
Description=WhatsApp Web Dashboard
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/wa-dashboard
ExecStart=/opt/wa-dashboard/wa-dashboard
Restart=on-failure
RestartSec=5

# Authentication credentials
Environment="AUTH_USERNAME=your_username_here"
Environment="AUTH_PASSWORD=your_secure_password_here"

# Optional: port override (default 8080)
Environment="PORT=8080"

[Install]
WantedBy=multi-user.target

Step 3 — Apply changes

sudo systemctl daemon-reload && sudo systemctl restart wa-dashboard
⚠️
Security note: Avoid using special characters like " or $ unescaped in the password value. Prefer using EnvironmentFile=/etc/wa-dashboard.env for sensitive values, with the file chmod'd to 600 and owned by root.

Alternative — Using an environment file (recommended for secrets)

# /etc/wa-dashboard.env  (chmod 600, owner root)
AUTH_USERNAME=admin
AUTH_PASSWORD=supersecret
# In [Service] section, replace Environment= lines with:
EnvironmentFile=/etc/wa-dashboard.env

⚡ §3 — Ping Tool Best Practices

⚠️
Rate Limiting Warning
Use intervals of 3+ seconds to avoid WhatsApp rate limiting and account bans. Sending too many messages too quickly can trigger WhatsApp's automated abuse detection, resulting in a temporary or permanent account suspension.
✅
Minimum 3-second intervals
Set the interval to at least 3 seconds between sends. For bulk operations (10+), use 5–10 seconds.
✅
Keep repeat counts reasonable
Avoid sending more than 20–30 messages in a single ping session. Split larger batches across time.
✅
Vary message content
Identical repeated messages are more likely to be flagged as spam. Personalize or vary content when possible.
✅
Use for legitimate purposes only
The ping tool is designed for reminders, alerts, and legitimate notifications — not bulk marketing or unsolicited messaging.
❌
Avoid sub-second or 1-second intervals
Even a few messages sent in rapid succession can trigger WhatsApp's rate limiter. 1-second intervals are not safe for counts above 3.
❌
Don't use on numbers that haven't messaged you
Sending messages to people who haven't initiated contact increases the spam report risk significantly.
💡
Recommended defaults: Count = 1–5, Interval = 5–10 seconds. For reminders to self: any count with 3+ second intervals is safe.

📁 §4 — Media Storage

All media received through WhatsApp is automatically downloaded and stored on disk. The /media/ endpoint serves these files to the browser.

Directory structure

./media/
├── images/     ← JPEG / PNG / WEBP images from chats
├── videos/     ← MP4 / MKV video files
├── audio/      ← OGG voice notes & audio messages
└── documents/  ← PDF, DOCX, XLSX, and other documents

Check disk usage

du -sh ./media/*/

Fix permissions (if media is not loading)

sudo chown -R www-data:www-data ./media/
sudo chmod -R 755 ./media/

Clean up old media (older than 90 days)

# Preview what would be deleted
find ./media/ -type f -mtime +90 -print

# Actually delete
find ./media/ -type f -mtime +90 -delete
ℹ️
Media files are referenced in the SQLite database by relative path. Deleting files manually will not break message history, but the media will display as a broken link in the UI. Run a vacuum on the DB if needed: sqlite3 messages.db "VACUUM;"

🛠️ §5 — Troubleshooting

Common issues and their solutions. Always check the logs first.

❓ QR code is not showing / blank QR page

The SSE stream from /api/qr is likely not connecting. Check the following:

sudo journalctl -u wa-dashboard -n 50 --no-pager
  • Look for QR generation failed or websocket error messages.
  • Ensure the server has internet access to reach WhatsApp servers.
  • Try restarting: sudo systemctl restart wa-dashboard
  • If the QR expires, it auto-refreshes every ~20 seconds — wait for a new one.
❓ Messages are not saving to the database

This is usually a file permission issue with the SQLite database.

# Check the DB file permissions
ls -la /opt/wa-dashboard/messages.db

# Fix ownership if needed
sudo chown www-data:www-data /opt/wa-dashboard/messages.db
sudo chmod 664 /opt/wa-dashboard/messages.db
  • Ensure the directory is writable by the service user (usually www-data).
  • Check for disk space: df -h
  • SQLite WAL mode must be enabled — check the application logs for WAL errors.
❓ Service is not starting / crashes immediately

Check whether the Go binary was compiled correctly and is executable.

# Check binary exists and is executable
ls -la /opt/wa-dashboard/wa-dashboard
file /opt/wa-dashboard/wa-dashboard

# Try running it manually to see errors
cd /opt/wa-dashboard && ./wa-dashboard

# Check if the port is already in use
sudo ss -tlnp | grep :8080
  • Recompile if needed: cd /path/to/source && go build -o wa-dashboard .
  • Ensure GOARCH and GOOS match your server (e.g. linux/amd64 or linux/arm64).
  • Check all required environment variables are set in the service unit.
❓ Dashboard shows "Disconnected" after successful QR scan

The WhatsApp session may have been invalidated or the credentials file is missing.

# Check if session store exists
ls -la /opt/wa-dashboard/session/

# Remove old/corrupted session and re-pair
sudo systemctl stop wa-dashboard
rm -rf /opt/wa-dashboard/session/
sudo systemctl start wa-dashboard
  • After removing the session, re-scan the QR code from the dashboard.
  • On WhatsApp mobile: Settings → Linked Devices → Remove old entries if shown.
❓ Media files (images, videos, audio) not loading

The /media/ route may not be serving files, or file permissions are wrong.

# Test media endpoint directly
curl -I http://localhost:8080/media/images/test.jpg

# Fix media directory permissions
sudo chown -R www-data:www-data /opt/wa-dashboard/media/
sudo chmod -R 755 /opt/wa-dashboard/media/
❓ Ping or Schedule API returns 500 errors

Check if the WhatsApp client is connected and the phone number format is correct.

  • Phone numbers must include the country code without + (e.g., 919876543210 for India).
  • The recipient must have a WhatsApp account.
  • Ensure the service is in connected state before sending (green status indicator).
  • Check application logs: sudo journalctl -u wa-dashboard -f
🆘
Still stuck? Always run sudo journalctl -u wa-dashboard -n 100 --no-pager and look at the last error lines. Most issues are clearly logged with the error reason.
